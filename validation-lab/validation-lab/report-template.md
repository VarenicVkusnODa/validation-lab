# Отчёт по практической работе

## Цель
Сформировать навык двухуровневой валидации: клиентской для удобства пользователя и серверной для безопасности и целостности данных.

## Реализованное решение
Создана форма регистрации на HTML/CSS/JavaScript и сервер Express. Клиентская проверка выполняется при потере фокуса и отправке формы. Сервер повторно проверяет все поля, возвращает HTTP 400 с объектом `errors` при ошибках и HTTP 201 при успешной регистрации. В ответе успешной регистрации пароль отсутствует.

## Структура
`package.json`, `server.js`, `public/index.html`, `public/style.css`, `public/app.js`, `bad.json`, `good.json`.


## Таблица соответствия правил
| Поле | Клиент | Сервер | Совпадают |
|---|---|---|---|
| name | 2–50 символов, буквы, пробел, дефис; начинается с буквы | Те же правила | Да |
| email | Формат local@domain.tld, домен не менее 2 букв, максимум 254 символа | Те же правила | Да |
| password | 8–72 символа, заглавная/строчная латинская буква и цифра | Те же правила | Да |
| age | Целое число 18–120 | Те же правила | Да |
| phone | +7 и 10 цифр; пробелы, скобки и дефисы допустимы | Те же правила, нормализация | Да |

## Протокол проверки

| Сценарий | Запрос | Ожидаемый результат |
|---|---|---|
| Неверные данные | `bad.json` | HTTP 400; JSON с ошибками по полям |
| Корректные данные | `good.json` | HTTP 201; телефон `+79991234567`; пароля в ответе нет |
| Ошибка JSON | Отправить синтаксически некорректное JSON-тело | HTTP 400 и ошибка `body` |
| Обход клиентской проверки | Отключить JavaScript или отправить запрос напрямую через curl | Сервер отклоняет некорректные данные с HTTP 400 |


## Вывод
Клиентская валидация повышает удобство и помогает пользователю исправить ошибки до отправки формы, однако её можно обойти, поскольку браузер находится под контролем пользователя. Поэтому сервер самостоятельно проверяет данные, не полагаясь на клиент. Сервер возвращает структурированные ошибки и не включает пароль в успешный ответ. Дублирование правил на двух уровнях обеспечивает проверку и при обычной работе формы, и при прямом обращении к API.

## Дополнительные задания повышенной сложности

| Реализация | Результат |
|---|---|
| Общий `rules.js` | Правила применяются и браузером, и сервером |
| Уникальность email | Повторная регистрация возвращает HTTP 409 Conflict |
| bcryptjs | Пароль хранится как хеш, не включается в ответ |
| Helmet | Устанавливает дополнительные HTTP-заголовки безопасности |
| Лимит JSON 10 КБ | Большие запросы отклоняются кодом 413 |
| Rate limiting | 60 запросов за 15 минут с одного IP |
| CSRF | CSRF-защита особенно важна при cookie-based авторизации; для защиты используют CSRF-токены, SameSite и проверку Origin |

Внимание: список пользователей хранится в памяти процесса, поэтому очищается при перезапуске.
