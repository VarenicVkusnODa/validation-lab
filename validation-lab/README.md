# validation-lab

## Запуск

1. Установите Node.js 18 или новее.
2. В терминале перейдите в папку проекта.
3. Выполните:

```bash
npm install
node server.js
```

4. Откройте http://localhost:3000

## Проверка серверной валидации

Отправьте некорректный запрос (должен вернуться HTTP 400 с errors):

```bash
curl -i -X POST http://localhost:3000/api/register -H "Content-Type: application/json" --data-binary "@bad.json"
```

Отправьте корректный запрос (должен вернуться HTTP 201; пароль не включён в ответ):

```bash
curl -i -X POST http://localhost:3000/api/register -H "Content-Type: application/json" --data-binary "@good.json"
```

В Windows PowerShell используйте `curl.exe` вместо `curl`.

## Дополнительные задания (Приложение В)
- Общие правила вынесены в `public/rules.js`, модуль подключается в браузере и импортируется сервером.
- Повторный email в памяти отклоняется с кодом HTTP 409.
- Пароль хешируется через bcryptjs до сохранения; хеш и пароль не возвращаются клиенту.
- Подключён Helmet для HTTP-заголовков безопасности.
- Тело JSON ограничено 10 КБ.
- Rate limiting: не более 60 запросов на IP за 15 минут.
- CSRF-защита важна для cookie-based сессий: атакующий сайт может инициировать запрос от имени авторизованного пользователя. Для реального приложения нужны CSRF-токены или SameSite cookies и проверка Origin; в данном учебном приложении с API без авторизационной cookie риск ограничен.

Данные пользователей и уникальность email хранятся только в оперативной памяти и сбрасываются при перезапуске сервера. Это учебная реализация, не постоянная база данных.
